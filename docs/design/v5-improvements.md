# Improvement of V5 — หน้าสาธารณะและความคิดเห็น

Branch `improvement-of-v5` (แยกจาก `main` ณ `1fffedd`) เอกสารนี้บันทึกสิ่งที่แก้และข้อจำกัดของการตรวจ
ยังไม่ได้ deploy และยังไม่ได้ตรวจบน AWS จริง

## สิ่งที่เปลี่ยน

| หัวข้อ | พฤติกรรมใหม่ | ไฟล์หลัก |
| --- | --- | --- |
| ป้ายภาษาไทย | ประเภทคู่ความร่วมมือ ประเภทกิจกรรม และสถานะ แสดงเป็นภาษาไทยทุกจุด (การ์ดหน้าแรก, รายละเอียด, คำแนะนำการค้นหา, ตัวกรองตามสิทธิ์) รหัสที่ไม่รู้จักแสดงตามเดิม ไม่เดาความหมาย | `public/assets/script.js`, `records.js` |
| หน้าโล่งตอนโหลด | เรียก `/fetchPartnersData` และ `/api/public/records` พร้อมกันแทนเรียงกัน, แสดงโครงร่างข้อความ hero ระหว่างรอ intro, แสดงการ์ดโครงร่างใน grid ระหว่างโหลดครั้งแรก animation เดิมไม่ถูกแก้ | `script.js`, `improvements.css`, `index.html` |

| สรุปด้วย AI | Staff/Executive ขอสรุปความคิดเห็นของรายการได้ **ปิดไว้เป็นค่าเริ่มต้น** จนกว่าจะตั้งค่า model | `feedback_summary.py`, `infra/backend.yaml` |

การจำกัดอัตราการส่งความคิดเห็น (20 ครั้งต่อ 5 นาทีต่อ IP) มีอยู่ก่อนแล้ว งานนี้เพิ่มเฉพาะของการรายงาน (5 ครั้ง) และการขอสรุป (10 ครั้ง)

## เส้นทาง API ที่เพิ่ม

| Method | Path | ผู้ใช้ | หมายเหตุ |
| --- | --- | --- | --- |
| PUT | `/api/public/{partners\|activities}/{id}/feedback/{feedbackId}/report` | ทุกคน (anonymous session + CSRF) | body `{"reason": "spam"\|"abuse"\|"personal_data"\|"other"}`; นับหนึ่งครั้งต่อเครือข่ายต่อความคิดเห็น คำตอบไม่บอกว่าถูกซ่อนแล้วหรือไม่ |
| PUT | `/api/{partners\|activities\|exchanges}/{id}/feedback/{feedbackId}/moderation` | Staff/Executive ใน scope | body `{"state": "hidden"\|"visible"}` พร้อม `If-Match` |
| GET | `/api/{partners\|activities\|exchanges}/{id}/feedback-summary` | Staff/Executive ใน scope | คืน `summary: null` เมื่อมีความคิดเห็นน้อยกว่า 3 รายการ; `503 SUMMARY_UNAVAILABLE` เมื่อยังไม่ตั้งค่า model |

ทั้งสามเส้นทางอยู่ใต้ `ANY /api/{proxy+}` เดิม ไม่ต้องเพิ่ม route ใน API Gateway

ฟิลด์ใหม่ในแถว feedback: `reports`, `moderation`, `moderatedBy`, `moderatedAt` และแถว `feedbackReport`
(เก็บเหตุผลและ digest แบบ HMAC ของผู้รายงาน ไม่เก็บ IP)

## การเปิดใช้สรุปด้วย AI

1. เปิดสิทธิ์ใช้ model ใน Amazon Bedrock ของบัญชีและ Region ที่ใช้
2. ส่งพารามิเตอร์ `FeedbackSummaryModelId` ให้ `infra/backend.yaml` เป็น model id หรือ inference profile id ที่เปิดไว้
   template จะเพิ่มสิทธิ์ `bedrock:InvokeModel` และตัวแปร `FEEDBACK_SUMMARY_MODEL_ID` ให้เอง ถ้าเว้นว่างจะไม่เพิ่มทั้งสองอย่าง
3. ถ้า model อยู่คนละ Region กับ Lambda ให้ตั้ง `FEEDBACK_SUMMARY_REGION` เพิ่ม

สิ่งที่ส่งออกไปยัง model มีเฉพาะข้อความความคิดเห็น ข้อเสนอปรับปรุง และกลุ่มผู้ตอบ ไม่ส่งชื่อผู้ตอบ
ความคิดเห็นที่ถูกซ่อนไม่ถูกนำไปสรุป การเรียกใช้มีค่าใช้จ่ายตามราคา Bedrock ของ model ที่เลือก

## สิ่งที่ยังไม่ได้ตรวจ

- ยังไม่ได้ deploy Lambda หรือหน้าเว็บ และยังไม่ได้ทดสอบกับ DynamoDB จริง
- ปุ่มซ่อน/แสดงของเจ้าหน้าที่และปุ่มสรุปด้วย AI ตรวจผ่าน unit test เท่านั้น ยังไม่ได้ลองในเบราว์เซอร์ด้วยบัญชีที่ login
- การเรียก Bedrock จริงยังไม่ได้ทดสอบ (ทดสอบด้วย client จำลอง)
- ชุด Playwright (`npm run test:e2e`) ไม่ได้รันในรอบนี้

## ข้อสังเกตสำหรับทีม

- ข้อมูลจำลอง `PART-*` / `ACT-*` ยังแสดงบนหน้าสาธารณะร่วมกับข้อมูลจริง งานนี้ไม่ได้แตะข้อมูล
- กิจกรรมที่มีวันที่ทั้งหมดในข้อมูลปัจจุบันสิ้นสุดแล้ว มุมมอง “ปัจจุบัน” จึงมีเฉพาะรายการที่ยังไม่ระบุวันที่ จนกว่าจะมีกิจกรรมใหม่
- ผู้ใช้ที่อยู่หลัง IP เดียวกัน (เช่น Wi-Fi มหาวิทยาลัย) นับเป็นผู้รายงานรายเดียว เป็นการแลกเพื่อกันคนเดียวซ่อนความคิดเห็นได้เอง เจ้าหน้าที่ยังซ่อนเองได้ทันที
