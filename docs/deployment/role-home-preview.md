# ทดลองแยกหน้าแรกตามบทบาท

- Guest / Student ใช้ `index.html` พร้อมหน้าค้นหาสาธารณะและ animation เดิม นักศึกษามีทางเข้าโครงการแลกเปลี่ยนของตนเอง
- อาจารย์/ผู้ประสานงาน (`coordinator`), เจ้าหน้าที่ (`staff`), ผู้ดูแลความร่วมมือ (`executive`) ใช้ `work.html` หลังเข้าสู่ระบบ
- ใช้เฉพาะ active grants จาก server บัญชีหลายบทบาทที่มีสิทธิ์ภายในจะเข้าหน้าทำงาน
- หน้าทำงานมีเมนูชนิดข้อมูล ปุ่มเพิ่มตามสิทธิ์ และรวม Feedback ส่วนภาพรวมและจัดการสิทธิ์แสดงตามสิทธิ์เดิม
- ดูหน้าสาธารณะได้ผ่าน `index.html?public=1` ไม่วนกลับหน้าทำงาน
- ไม่มี role ภายในจะถูกส่งกลับหน้าแรกหรือหน้าเข้าสู่ระบบ ตรวจสิทธิ์ไม่สำเร็จแสดงปุ่มลองใหม่
- `npm run build` สร้าง `public/work.html` จาก `public/index.html` และ `public/partials/work-home.html` ใช้ฟอร์ม/รายละเอียดชุดเดิม
- Branch ทดลอง `role-home` ไม่ได้แยก Lambda, DynamoDB หรือ S3 การบันทึกผ่าน API เดิมยังเปลี่ยนข้อมูลจริง ต้องใช้เฉพาะรายการที่ตั้งใจทดสอบ
- การแยกหน้าไม่ได้เพิ่มสิทธิ์ API ทุกคำขอยังตรวจ session, role และ scope ที่ backend

## การตรวจรอบนี้

ตรวจ build, syntax และการเลือกหน้าสำหรับ Guest/Student/Coordinator/Staff/Executive รวมถึง inactive grants ผ่าน ตรวจหน้าทำงานและการเปิดฟอร์มกิจกรรมด้วย session จำลองในเครื่อง ไม่ได้ใช้ผลนี้แทนผล AWS จริง

## เว็บทดลองที่เชื่อมแล้ว

- https://role-home.d1d0za87xu48iv.amplifyapp.com/ เชื่อม GitHub branch `role-home` พร้อม Auto-build
- Lambda `CSTUHubAuth` เพิ่ม origin เฉพาะ URL ทดลองใน `SESSION_ADDITIONAL_ORIGINS` ตามที่เจ้าของงานอนุมัติ คง origin เดิมไว้
- ทดสอบ Login จริงด้วยบัญชีทดลอง Student เข้าหน้า `index.html` และ Coordinator เข้าหน้า `work.html` ถูกต้อง Student เปิดหน้าทำงานแล้วกลับหน้าแรก
- ตรวจหน้าจอ 390px ไม่มีเนื้อหาล้นแนวนอน ไม่ได้สร้างหรือแก้ข้อมูลธุรกิจในรอบตรวจนี้

## กระดานข้อเสนอความร่วมมือ
เปิด `work.html?view=proposals` จากการ์ดแรกหรือเมนูซ้าย บัญชีภายในโพสต์ข้อเสนอและแสดงหรือถอนความสนใจของตัวเองได้ ปิดรับเมื่อพ้นวันที่กำหนดตามเวลาไทย ผู้สนใจแยกจากผู้ดำเนินงานจริง การส่งต่อและขั้นตอนอนุมัติรอยืนยันจากผู้ใช้

เว็บทดลองที่ยังได้รับ `404 NOT_FOUND` จาก `GET /api/proposals` แสดงกระดานตัวอย่างและเก็บการลองใช้ใน sessionStorage ของบัญชี/ขอบเขตในแท็บนั้น เมื่อเปิด API บน Lambda แล้ว ข้อมูลร่วมกันจะอยู่ในตาราง BUSINESS_TABLE เดิม แยกตาม scope ผ่าน `GET /api/proposals`, `POST /api/proposals` และ `PUT /api/proposals/{id}/interest` ข้อมูลตัวอย่างไม่ถูกนำเข้าตารางจริง
